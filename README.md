CASTÚO-SYSTEM is an evidence and recovery layer for resilient rural and distributed operations. The first commercial wedge is **CASTÚO Evidence-Ready Field Operations**: offline-first continuity, traceability and verifiable evidence for workflows operating with irregular connectivity.

AI, Edge/IoT, federation, sovereignty and private cloud are enabling architecture. They are not separate products or claims of current production operation.

## What the customer gets first

The initial customer journey is intentionally simple:

```text
Create organisation → connect a source → register an operation
→ continue through connectivity loss → synchronise → review evidence → export a report
```

| Value layer | Customer value | Current public state |
|---|---|---|
| Field continuity | Local capture, offline work, synchronisation and recovery | Documented direction; field evidence pending |
| Evidence operations | Identity, permissions, logs, hashes, review and export | Governance implemented; dossier promotion pending |
| Governed AI assistant | Bounded agent, read-only tools, default deny and evidence | G-AI-FED-001 dry-run; not a production claim |

The first operational problem is continuity and evidence under irregular connectivity. The technical architecture exists to make that workflow safer and more traceable; it does not replace the workflow or measured customer value.

## Evidence chain

```text
Claim → Evidence → Execution → Hash → Reproduction → Independent review → Gate → Promotion / rollback
```

Repository activity never equals operational truth. A commit, issue, roadmap, badge or green workflow does not prove production, customer adoption, certification, autonomy, federation, recurring revenue or continuous operation.

The public evidence model distinguishes **objectives**, **observed results** and **published claims**. A template is not a pilot; a pilot is not continuous operation; and a hash is not certification.

## G-AI-FED-001

The first governed objective is **G-AI-FED-001 — Governed Multi-Agent Dry Run**: registered agents, a coordinator without physical permissions, three bounded tools, default deny, evidence envelopes, revocation, negative tests, replay and human review for sensitive actions. Physical and financial actions remain outside the first Gate.

The current public state is architectural and documentary. The runtime, federated nodes, production operation and independent review remain pending. Federation will not be claimed until a second real node, verified identity, tested exchange and synchronisation evidence exist.

The multi-agent governance contract, federated node model and G-AI-FED-001 specification are maintained in the private control plane. The public surface is the [Evidence Center](https://github.com/Traky12/Traky12/tree/main/evidence-center); the underlying documents remain scope-bound and are not presented as public production evidence.

## Security and boundaries

Security is described as a fail-closed and recoverable model: detect, contain, preserve evidence, remediate, recover, verify and learn. Actual control status remains scope-bound to implementation and evidence. Local or simulated blockchain identifiers are not public blockchain confirmations.

Public documentation remains plaintext, readable, auditable and scoped. Secrets, credentials, private keys, customer data and restricted operational evidence do not belong in versioned Markdown.

The following are **not claimed** from this profile: production operation, autonomous authority, federation, certification, independent validation, regulatory conformity, paid customer traction, recurring revenue, private-cloud provisioning, operational robotics, semiconductor manufacturing or universal interoperability.

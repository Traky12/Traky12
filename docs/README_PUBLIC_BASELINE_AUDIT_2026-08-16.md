# README Public Baseline Audit — 2026-08-16

## Observación principal

El README ya comunica con claridad la identidad, la primera oferta comercial, la filosofía de provenance y los límites de producción, autonomía, federación y financiación. Su fricción principal es la densidad: mezcla entrada pública, arquitectura, gobernanza, seguridad, private cloud, comercialización, evolución y cronología en un único recorrido largo.

## Claims públicamente bien acotados

- La primera propuesta es `CASTÚO Evidence-Ready Field Operations`.
- AI, Edge/IoT, federation y sovereignty se presentan como arquitectura habilitadora, no como productos sueltos.
- El estado multiagente se declara arquitectónico/documental; G-AI-FED-001 permanece como dry-run y no como producción.
- La operación productiva, federación, revisión independiente, clientes recurrentes, contratos pagados y revenue no se declaran.
- El modelo de evidencia distingue objetivos, resultados observados y claims publicados.

## Fricciones detectadas

- El recorrido inicial es demasiado largo para una primera interfaz.
- Muchos enlaces profundizan antes de que el visitante vea un mapa compacto de evidencia y siguiente Gate.
- El perfil contiene dos taxonomías de estado parcialmente solapadas: la cadena pública comercial y los niveles E1–E3/Operational.
- Algunos documentos enlazados desde el README son anteriores al baseline V1.0 o pueden no existir en el HEAD remoto auditado; deben mantenerse como enlaces condicionados o revisarse antes de presentarlos como evidencia.
- El README remoto enlaza a la auditoría y al Evidence Center, pero el conformance report repo por repo todavía no forma parte de la entrada pública.

## Recomendación de reducción

Mantener arriba únicamente identidad, oferta inicial, estado actual, evidencia verificable, siguiente Gate, mapa de repositorios y limitaciones. Mover la arquitectura profunda, private cloud, seguridad detallada, cronología y estrategia comercial a `castuo-evolution`, Evidence Center, `Castuo-system`, `goldfish` y `Cast-o`.

## Claims bloqueados o condicionados

Producción, autonomía, federación, certificación, validación independiente, paid traction, recurring revenue, private-cloud provisioning, robotics, semiconductor manufacturing, universal interoperability y secure-build deben permanecer condicionados a evidencia específica y no aparecer como hechos actuales.
